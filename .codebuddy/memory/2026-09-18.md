## 踩坑：测试替身的 hook 模型是错的（已修）

`tests/client.spec.js` 的 `fakeReact` 原先把 hook 槽位按**整棵树第几个 hook** 分（单一扁平游标），
于是展开表单多挂 4 个 hook 会把**后面所有行**的槽位挤位——第 4 行读到别人的 `draft`，
`ruleDraftProblem` 里 `draft.label.trim()` 直接抛。真机 React 状态属于组件实例，不会这样。
修法：`evaluate(element, depth, react, path)` 求值组件前 `react.__enter(路径)`，槽位键变成 `路径#序号`
（effect 是 `路径$序号`，`frame.registered` 去重、`effects` 存 `{key, effect}`、`ran` 用 Set）。
后果：以后可以放心条件挂载带 hook 的组件了。**用例侧新增动作序列助手**：`steps(...)`（一步一帧，
同一帧里连着点会把旧值发出去）、`expandRow()` / `openToggle('debug-info'|'rule-entry')` / `clickKind()` /
`fillInput()` / `clickScopeButton()`；`promoteOnce` 因此多了一步「点开入口」。
`pnpm test` 202 用例全绿（client 31）。

## 第四轮收尾：宽度超 100% 修复（用户真机反馈）

用户：**「宽度有点问题，超过 100% 了；两侧边距再大一点」**。两个根因都查实了：

1. **`box-sizing` 不继承**：客户端只在 `.ap-root` / `.ap-card` 上写了 `border-box`，子元素仍是 content-box——
   `.ap-rowHead` 的 `width:100%` + `padding` 把内边距加到宽度之外，正好超出 100%。修法：面板内部统一
   `.ap-root,.ap-root *{box-sizing:border-box}`（预览页一直有全局 reset，所以预览里看不出来——**预览与真机的差异点要记这个**）。
2. **两侧 0 边距**：整块背景与分割线贴着面板边缘。修法：`.ap-list{padding:2px 12px 12px}`（与头部/筛选条对齐），
   轨道/按天分组/展开背景/分割线全部以它为界；`.ap-rowHead` 改 `padding:7px 0`（左右边距交给列表统一给）、
   `.ap-detailBox` 改 `padding:8px 0 10px 18px`。

CSS 自查脚本（拼出注入的样式串断言配平 + 关键声明）确认修复；206 用例全绿。

## 第四轮又一次微调（用户截图反馈）

1. **行尾徽标没贴右边**：真机截图显示 `自动批准` 徽标与右边缘之间空了一截。修法：右侧徽标（自动写入标识 /
   结论 / 结果）独立成组 `.ap-rowBadges{margin-left:auto}`，**不再用空的 `.ap-grow` 撑开**——那个空 span
   在真机上被宿主样式影响过（面板头部的 `.ap-grow` 仍在用，别删类）。
2. **折叠卡的 ▸/▾ 文字箭头换掉**（太细不好看）：`BlockChevron` 内联 SVG（`M6 3.5 10.5 8 6 12.5`，stroke
   currentColor 1.6 round），`.ap-blockHead[aria-expanded="true"] .ap-blockChevron{transform:rotate(90deg)}`
   + 0.15s 过渡；颜色跟随卡头 hover。
3. **徽标右对齐彻底失效的根因（重要教训）**：`margin-left:auto` 也不生效 → 容器没有可分配空间 →
   **`.ap-rowHead` 是 `<button>`，button 的宽度默认按内容收缩，`display:flex` 也不会让它撑满父级**——
   旧代码里的 `width:100%` 正是为此而写，重构时被当成冗余删掉。已恢复（   面板统一 border-box 后
   100% + 内边距不会再溢出）。**教训：凡是 `<button>` 当整行容器用，必须显式 `width:100%`。**
